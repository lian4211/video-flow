# Storytelling：讲解视频的结构与文案

## 1. 四种结构，按内容选一个

### A. 因果链（理科/工程首选）
> 现象 → 矛盾 → 拆解 → 验证 → 边界 → 系统 → 收束

例：ALU：一条指令 → 32 种运算却只有一套加法器 → 74181 → 减法验证 → 级联瓶颈 → 标志位 → CPU。
优点：每一步回答“为什么”，观众不会掉线；适合公式多、结构复杂的内容。

### B. 问题 → 解法 → 验证
> 痛点 → 旧方案为什么不行 → 新方案 → 反例/边界 → 适用条件

适合产品、算法、工程方案、工具介绍。

### C. 误区 → 纠正 → 迁移
> 常见直觉 → 一个反例 → 正确模型 → 再解释两个现象

适合科普、物理、生物、经济；**开头先让观众“发现自己错了”**，注意力最稳。

### D. 时间线 / 流程
> 起点 → 关键节点（3–6 个）→ 转折 → 今天

适合历史、行业发展、项目复盘、操作教程。

## 2. 1–5 分钟的节奏表

| 时长 | 镜头数 | 每镜时长 | 结构 |
|---|---|---|---|
| 30–60 s | 4–6 | 6–10 s | 开场钩子 + 1 个核心 + 1 个验证 + 收束 |
| 1–2 min | 6–9 | 8–15 s | 完整 A/B/C 结构 |
| 2–4 min | 8–12 | 12–20 s | 多一轮“边界/反例”，加总结 |
| 4–5 min | 10–16 | 15–25 s | 分 2–3 章，每章一个小结 |

**开场 2 秒**必须有信息：一句反直觉的话、一个数字、一个动作、或一个问题。不要“大家好，今天我们来学习……”。

**每 2–4 秒**要有一个变化：元素出现/数字变化/镜头推近/颜色切换/图表生长。变化不等于闪烁。

**结尾**只做一件事：一句可复述的结论 + 一个可迁移的动作（考点/步骤/判断）。

## 3. 屏幕字 vs 旁白

| 屏幕 | 旁白 |
|---|---|
| 关键词、数字、公式、结论 | 解释、因果、例子、转折 |
| 标题 ≤ 18 字；正文每行 ≤ 22 字 | 每句 ≤ 30 字；一段 1–3 句 |
| 一屏最多 1 个结论 + 3 个支撑点 | 可以更口语，允许“你”“我们” |
| 停留 ≥ 2.5 s | 语速约 4–5 字/秒 |

**不要让屏幕字和旁白逐字重复**：屏幕是提词，旁白是讲课。

## 4. 文案检查清单

- [ ] 第一句是否制造了“为什么/然后呢”？
- [ ] 每个镜头是否只有一个中心思想？
- [ ] 有没有“首先/其次/最后”这种没有信息量的连接词？删掉。
- [ ] 数字/年份/公式是否都能在源材料找到？不确定的标 `[待核实]`。
- [ ] 是否有至少一个“反例/边界/易错点”？没有的话，加一个，理解会深一倍。
- [ ] 最后一句能否被观众原样复述？
- [ ] 竖屏版本是否每行 ≤ 14 字？横屏 ≤ 22 字？

## 5. 不同题材的“钩子”模板

- **科学**：“你以为是 A，其实是 B。” / “同一个现象，两种解释，差在哪？”
- **工程**：“一条指令，在 0.3 纳秒里发生了什么？”
- **历史**：“如果当时没有这一步，后面全都会改写。”
- **产品**：“这个功能解决的不是效率，而是信任。”
- **教程**：“90% 的人第一步就做反了。”
- **数据**：“这张图里最容易被忽略的，是这条线。”

---

## 6. 事实与引用

- 每个事实句在 `script.json` 里用 `sources` 数组存来源（文件名 + 页码/URL）。
- 公式注明变量含义；数字保留单位与量级。
- 不确定的内容：旁白不写死，屏幕标 `[待核实]`，交付时单列。
- 不要为了“顺口”改数字；宁可说“大约”。

---

## 7. 视觉隐喻库（让抽象变具体）

| 抽象 | 可视化 |
|---|---|
| 复用/多态 | 一个核心 + 多个输入开关 / 一个角色换装 |
| 流程 | 管道、传送带、箭头链 |
| 反馈/闭环 | 环形箭头、循环轨道 |
| 层级 | 堆叠方块、剖面、放大镜 |
| 对比 | 双栏、天平、前后帧 |
| 瓶颈 | 窄口、排队、红色拥堵段 |
| 溢出/边界 | 容器装满、越界红线 |
| 时间 | 横向刻度、生长年轮 |
